# Роадмап LAST CALL

PC в первую очередь; кампания выходит раньше коопа; у вехи нет даты. **v1.0 выходит, когда завершены Track A и Track C** — цикл дня проходит от начала до конца со сюжетным позвоночником, на собственном контенте.

Статус: `[ ]` не начато, `[~]` в работе, `[x]` готово. У вех нет дат.

Веха закрывается только когда её **пользовательский путь проходит от начала до конца** — сценарным тестом или живым прогоном, — а не когда зелёные юниты (см. [ARCHITECTURE.ru.md](ARCHITECTURE.ru.md) §10).

## Track F: фундамент (прототип)

- [ ] **F0. Скелет проекта (гейт).** Проект UE5 собирается на Linux и Windows; модули `Source/LastCall` компилируются; валидация схем `Data/` и линт диалогов идут в CI; языковые пары документов связаны в обе стороны.
- [ ] **F1. Один налив.** Солвер двигает бутылку, струю и стакан: наклон → расход, объём растёт, перелив льётся, клиент реагирует. Это гейт для всего остального — никакая другая веха не начинается, пока посторонний не может пролить напиток на камеру.
- [ ] **F2. Один день.** `ULCPhaseManager` гонит Утро → Смена → Ночь → Итог с плейсхолдерами и сейвом на каждой границе.
- [ ] **F3. Один клиент.** Терпение, настроение, один заказ, одна история, одна примета; прерывание имеет записанное последствие.

## Track A: бар (ядро)

- [x] **A0. Набор документации.** Философия, архитектура, роадмап, чейнджлог, контрибьюшн, кодекс, безопасность, версионирование — на EN и RU, плюс гейм-дизайн, нарратив, арт, языки, каталог ассетов и режим документов (13.10.2026).
- [ ] **A1. Ядро жидкостей.** Многослойные стаканы, вязкость на жидкость, пена, декали пролитого, оценка комбо из вывода солвера.
- [ ] **A2. Библиотека рецептов.** Рецепты на данных, фирменный напиток, крючок твиста «рецепты на стене» как данные, эффекты на настроение/чаевые.
- [ ] **A3. Экономика.** Поставщики, суточный сток, цены, зарплаты, займы; утро — реальное решение, а не экран магазина.
- [ ] **A4. Клиенты как люди.** Завсегдатаи с расписаниями и вкусами, приметы языка тела, оценка угрозы «шестым чувством».
- [ ] **A5. Социальные последствия.** Фракционно значимые флаги за то, как вы слушали истории; таблицы реакций; без шкалы добро/зло.
- [ ] **A6. Древо навыков.** Флейринг, Психология, Крепкие нервы, Алхимия — четыре ветки, все ведут в налив или чтение зала.
- [ ] **A7. Крафт.** Настойки и сиропы как новые строки данных; эксперименты, которые могут провалиться; квестлайн фирменного коктейля.
- [ ] **A8. Разрушаемость.** Бутылки как оружие, перевёрнутые столы, сифон как огнетушитель — набор взаимодействий для смены и для ночи.

## Track B: ночь (экшн / стелс)

- [ ] **B1. Ночной режим.** Свой набор управления, укрытия, бар как уровень после закрытия.
- [ ] **B2. Заказы «на вынос».** Бронированное окно: быстрая сборка под давлением времени, пока снаружи ждёт город.
- [ ] **B3. Выборка долгов.** Кварталы города, инвентарь бара как оружие, нелетальные выигрыши предпочтительны.
- [ ] **B4. Директор обыска.** Просмотр полицией, теги улик, NPC-напарник прячет их, проверки на отвлечение в диалоге.
- [ ] **B5. Расследования.** Подслушанные разговоры как инвентарь; информация сильнее силы.

## Track C: история

- [ ] **C1. Сюжетный позвоночник.** Дядя, зашифрованные рецепты, город: бит-лист утверждён, написан на EN и RU.
- [ ] **C2. Трое завсегдателей.** Детектив Харрис, мисс Кейн, босс «Тень» — полные диалоговые деревья, расписания, последствия.
- [ ] **C3. Арки фракций.** Три группировки + полиция: пересекающиеся линии, без единого «правильного» лояла.
- [ ] **C4. Набор финалов.** Несколько концовок из репутации + информации + уровня заведения; каждая замыкает цикл дня.

## Track D: рост и кооп

- [ ] **D1. Развитие заведения.** Забегаловка → отремонтированный бар → VIP-этаж(а) → подпольное казино; планировка как данные, а не захардкоженные комнаты.
- [ ] **D2. Кооп 2–4.** Роли (бармен, официант, вышибала, диджей), listen server, реконнект = пауза, нагрузка толпой.
- [ ] **D3. Пул динамических событий.** Обыски, визиты знаменитостей, открытия конкурентов, отключения света — взвешено по репутации фракций.

## Track P: производство и релиз

- [ ] **P1. Вертикальный срез.** Один отполированный день + одна ночь + одна диалоговая арка, 15 минут для постороннего.
- [ ] **P2. Присутствие в сторе.** Двуязычная страница, трейлер, демо-сборка (демо = вертикальный срез).
- [ ] **P3. Цикл плейтестов.** Внешние тесты с чек-листами «ощущения налива» и читаемости из PHILOSOPHY §7–8.
- [ ] **P4. Релизная сборка.** Версионирование по [VERSIONING.ru.md](VERSIONING.ru.md), лицензии ассетов сверены с [docs/FREE-3D-MODELS.ru.md](docs/FREE-3D-MODELS.ru.md), без телеметрии (PHILOSOPHY §3).
- [ ] **P5. После релиза.** Правки локализации, баланс из репортов сообщества, дружелюбные к модам данные (Data/ отдаётся читаемым).

## Как работают вехи

- **Команда:** один разработчик с AI-агентами. Вехи берутся строго по порядку, по одной, и прорабатываются автономно от начала до конца — каждая приходит как проверяемый результат, а не как статус-апдейт.
- Одна веха, одна ветка, один проверяемый результат. Внутри трека вехи идут по порядку.
- Track F не начинался, пока F0 не собирался в CI; **F1 (налив) — гейт для всех геймплейных вех**.
- Каждая веха проходит линтеры данных и сценарный тест своего трека.
- Каждый шаг проверяет владелец; документация обновляется в том же изменении (см. [docs/MAINTENANCE.ru.md](docs/MAINTENANCE.ru.md)).
