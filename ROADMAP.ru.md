# Роадмап LAST CALL
**[English version of this file →](ROADMAP.md)**

PC в первую очередь; кампания выходит раньше коопа; у вехи нет даты. **v1.0 выходит, когда завершены Track A и Track C** — цикл дня проходит от начала до конца со сюжетным позвоночником, на собственном контенте.

Статус: `[ ]` не начато, `[~]` в работе, `[x]` готово. У вех нет дат.

Веха закрывается только когда её **пользовательский путь проходит от начала до конца** — сценарным тестом или живым прогоном, — а не когда зелёные юниты (см. [ARCHITECTURE.ru.md](ARCHITECTURE.ru.md) §10).

- [ ] **D1. Развитие заведения.** Забегаловка → отремонтированный бар → VIP-этаж(а) → подпольное казино; планировка как данные, а не захардкоженные комнаты.
- [ ] **D2. Кооп 2–4.** Роли (бармен, официант, вышибала, диджей), listen server, реконнект = пауза, нагрузка толпой.
- [ ] **D3. Пул динамических событий.** Обыски, визиты знаменитостей, открытия конкурентов, отключения света — взвешено по репутации фракций.

## Track P: производство и релиз

- [ ] **P1. Вертикальный срез.** Один отполированный день + одна ночь + одна диалоговая арка, 15 минут для постороннего.
- [ ] **P2. Присутствие в сторе.** Двуязычная страница, трейлер, демо-сборка (демо = вертикальный срез).
- [ ] **P3. Цикл плейтестов.** Внешние тесты с чек-листами «ощущения налива» и читаемости из PHILOSOPHY §7–8.
- [ ] **P4. Релизная сборка.** Версионирование по [VERSIONING.ru.md](VERSIONING.ru.md), лицензии ассетов сверены с [docs/FREE-3D-MODELS.ru.md](docs/FREE-3D-MODELS.ru.md), без телеметрии (PHILOSOPHY §3).
- [ ] **P5. После релиза.** Правки локализации, баланс из репортов сообщества, дружелюбные к модам данные (Data/ отдаётся читаемым).

## Как работают вехи

- **Команда:** один разработчик с AI-агентами. Вехи берутся строго по порядку, по одной, и прорабатываются автономно от начала до конца — каждая приходит как проверяемый результат, а не как статус-апдейт.
- **Ни секунды простоя на фоновой работе.** Пока качается файл, распаковывается архив, ставится движок или в фоне идёт любая долгая задача, агент берёт следующую автономную задачу; результаты обрабатываются, когда приходят (правило в [docs/MAINTENANCE.ru.md](docs/MAINTENANCE.ru.md) §6).
- Одна веха, одна ветка, один проверяемый результат. Внутри трека вехи идут по порядку.
- Track F не начинался, пока F0 не собирался в CI; **F1 (налив) — гейт для всех геймплейных вех**.
- Каждая веха проходит линтеры данных и сценарный тест своего трека.
- Каждый шаг проверяет владелец; документация обновляется в том же изменении (см. [docs/MAINTENANCE.ru.md](docs/MAINTENANCE.ru.md)).
