# Участие в LAST CALL
**[English version of this file →](CONTRIBUTING.md)**

Сначала прочитайте [PHILOSOPHY.ru.md](PHILOSOPHY.ru.md). Функция против её принципов будет отклонена, как бы хорошо она ни была сделана. Коротко:

1. **Слушать и наливать.** Механики должны вознаграждать внимание и физическое мастерство, а не нажатия кнопок.
2. **Без монетизационных уловок и телеметрии.** Одна цена; одиночная игра работает офлайн.
3. **Налив — это игра.** Любое изменение, делающее смешивание менее физичным или менее читаемым, не принимается.
4. **Двуязычные документы.** Каждый документ существует на английском и русском; правка одного означает правку двойника в том же изменении.

## Что нужно в первую очередь

Проект в предпродакшене (см. [ROADMAP.ru.md](ROADMAP.ru.md)). По полезности:

1. **Ревью дизайна** — пройдите концепцию в голове, найдите, где трёхфазный цикл становится скучным, и скажите об этом.
2. **Поиск референсов** — интерьеры баров, нуар-свет, видео наливания, техника барменов; складываем в issues.
3. **Бесплатные ассеты** — дополнения в [docs/FREE-3D-MODELS.ru.md](docs/FREE-3D-MODELS.ru.md) с проверенными лицензией и форматом.
4. **Тексты** — черновики диалогов EN/RU в тоне [docs/NARRATIVE.ru.md](docs/NARRATIVE.ru.md).
5. **Код** — стартует с вехи F0 ([ROADMAP.ru.md](ROADMAP.ru.md)); до этого приветствуются инструменты в `tools/`.

## Настройка

Нужны Unreal Engine 5.4+ (бесплатный лаунчер Epic Games), Git и C++ тулчейн, поддерживаемый движком (Visual Studio 2022 на Windows, clang на Linux/macOS). Инструменты пайплайна пишутся на Rust (см. [docs/LANGUAGES.ru.md](docs/LANGUAGES.ru.md)):

```bash
git clone <этот репозиторий>
cd GameBarmenSimulator
# движок: сгенерировать проектные файлы из LastCall.uproject, когда он появится
cargo test --manifest-path tools/Cargo.toml   # линтеры данных, когда появится tools/
```

Для правок документации нужен только текстовый редактор — это большая часть участия до выхода F1.

## Изменения в документации

- **Оба языка в одном изменении.** `FOO.md` и `FOO.ru.md` должны говорить одно и то же; ссылка в начале каждого файла ведёт на двойника.
- **Зафиксируйте** в `CHANGELOG.md` (+ двойник) в разделе `Unreleased`.
- **Иерархия:** PHILOSOPHY побеждает ARCHITECTURE, тот — ROADMAP и игровые документы. Не меняйте PHILOSOPHY без решения владельца с датой.
- Следуйте режиму из [docs/MAINTENANCE.ru.md](docs/MAINTENANCE.ru.md).

## Баги и идеи

- **Баг:** сначала поищите существующие issues, затем откройте новый: ОС, версия сборки ([VERSIONING.ru.md](VERSIONING.ru.md)), шаги, ожидание/факт.
- **Фича:** согласуйте в issue до написания крупного изменения.
- **Безопасность:** никогда в issues — по [SECURITY.ru.md](SECURITY.ru.md).

## Pull request

1. Ветка от `main`.
2. Одно логическое изменение на PR, связанное со своим issue.
3. Изменения документации: оба языка, запись в чейнджлоге, проверенные ссылки (в репозитории есть проверяльщик ссылок — см. [docs/MAINTENANCE.ru.md](docs/MAINTENANCE.ru.md)).
4. Изменения кода (с F0): сборка проходит на Linux и Windows, линтеры данных зелёные, кфиксу бага прилагается тест, который падает без него.

Все участники следуют [Кодексу поведения](CODE_OF_CONDUCT.ru.md).
