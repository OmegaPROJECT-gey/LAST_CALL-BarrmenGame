# Режим ведения документации
**[English version of this file →](MAINTENANCE.md)**

Как документацию LAST CALL читают и обновляют регулярно. Правило для участника: **документацию читают в начале каждой рабочей сессии и обновляют в том же изменении, что и то, что она описывает.**

## 1. Языковые пары

Каждый документ существует дважды, и пара должна говорить одно и то же:

| English | Русский |
| :--- | :--- |
| `README.md` | `README.ru.md` |
| `PHILOSOPHY.md` | `PHILOSOPHY.ru.md` |
| `ARCHITECTURE.md` | `ARCHITECTURE.ru.md` |
| `ROADMAP.md` | `ROADMAP.ru.md` |
| `CHANGELOG.md` | `CHANGELOG.ru.md` |
| `CONTRIBUTING.md` | `CONTRIBUTING.ru.md` |
| `CODE_OF_CONDUCT.md` | `CODE_OF_CONDUCT.ru.md` |
| `SECURITY.md` | `SECURITY.ru.md` |
| `VERSIONING.md` | `VERSIONING.ru.md` |
| `docs/GAME-DESIGN.md` | `docs/GAME-DESIGN.ru.md` |
| `docs/NARRATIVE.md` | `docs/NARRATIVE.ru.md` |
| `docs/ART-BIBLE.md` | `docs/ART-BIBLE.ru.md` |
| `docs/LANGUAGES.md` | `docs/LANGUAGES.ru.md` |
| `docs/FREE-3D-MODELS.md` | `docs/FREE-3D-MODELS.ru.md` |
| `docs/MAINTENANCE.md` | `docs/MAINTENANCE.ru.md` |

Правила:

1. **Оба файла — в одном изменении.** Правка одного файла без двойника — незавершённое изменение.
2. **Ссылка-двойник в начале каждого файла:** в англоязычных `**[Русская версия этого файла →](FOO.ru.md)**`, в русскоязычных `**[English version of this file →](FOO.md)**` (допустимы и ссылки в стиле README).
3. Числа, даты, версии, идентификаторы кода и URL не переводятся — в паре они должны совпадать байт в байт.
4. Двойники `CHANGELOG` держат одинаковые заголовки разделов и версии; текст внутри раздела может быть написан нативно на каждом языке.

## 2. Когда читать

| Момент | Что читаем | Зачем |
| :--- | :--- | :--- |
| **Начало каждой сессии по проекту** | `README` (текущий язык) → `ROADMAP` → `CHANGELOG` (верхний раздел) | Восстановить контекст: что решено, что дальше, что только что изменилось |
| **Перед любым изменением дизайна** | `PHILOSOPHY` — всегда | Он главенствует над всем, включая память о прошлых решениях |
| **Перед изменением кода/тулгов** | `ARCHITECTURE` + релевантный документ `docs/*` | Держать дизайн и реальность в синхроне |
| **Перед релизом** | `VERSIONING` + полный пересмотр `CHANGELOG` | Верные заголовки, оба языка, теги |
| **Раз в неделю (или после пачки работы)** | Полный проход по всем файлам | Поймать дрейф, пока он мал |

## 3. Когда обновлять

Документ обновляется **в том же изменении**, что и то, что он описывает, — никогда «потом»:

| Триггер | Что обновляем |
| :--- | :--- |
| Изменилось решение (стек, объём, тон, правило) | Сначала `PHILOSOPHY` (с датой владельца), затем документы, которые на него ссылались, затем `CHANGELOG` |
| Система добавлена/переименована/удалена | Таблица в `ARCHITECTURE` + раздел в `GAME-DESIGN` |
| Веха началась или завершена | Маркер статуса в `ROADMAP` `[ ] → [~] → [x]` |
| Изменился контент для игрока | `GAME-DESIGN` / `NARRATIVE` / `ART-BIBLE` |
| Добавлены или убраны бесплатные ассеты | `FREE-3D-MODELS` (имя, URL, лицензия, формат — все четыре обязательны) |
| Любое видимое пользователю изменение | Раздел в `CHANGELOG` под `Unreleased`, на релизе — с заголовком-версией |
| Обветшало исследование языков/движков (> 3 месяцев) | Освежить `LANGUAGES` — версии и даты меняются быстро |
| Сломалась ссылка или переименован файл | Немедленно в обоих языках |

В `PHILOSOPHY` правки возможны только от владельца и получают инлайновую штампованную дату; больше там ничего не меняет.

## 4. Чек-лист согласованности (перед каждым коммитом)

- [ ] Каждый отредактированный `FOO.md` получил `FOO.ru.md` в том же изменении
- [ ] Ссылка-двойник стоит в начале обоих файлов
- [ ] Все относительные ссылки разрешаются (нет битных `](путь)`)
- [ ] Идентификаторы, имена классов (`ULCPhaseManager`), версии (`b17`, `UE 5.8`), даты и URL совпадают в обоих языках
- [ ] Маркеры статуса в `ROADMAP` соответствуют реальности
- [ ] Новые решения записаны в `PHILOSOPHY` (владелец, с датой)
- [ ] Видимое изменение добавлено в `CHANGELOG` (+ двойник) под `Unreleased`
- [ ] Записи `FREE-3D-MODELS` всё ещё имеют рабочие URL и верные лицензии

Быстрая проверка ссылок из корня репозитория:

```bash
grep -oh '](\([^)#]*\)' *.md docs/*.md | sed 's/](//' | grep -v '^http' | sort -u | while read -r f; do
  [ -e "$f" ] || [ -e "docs/$f" ] || echo "MISSING: $f"
done
```

## 5. Проходы пересмотра

1. **Начало сессии** — чтение (§2), писать не обязательно.
2. **Конец сессии / коммит изменения** — обновление (§3), чек-лист (§4), коммит документации вместе с изменением.
3. **Полный проход раз в неделю** — прочитать каждый файл от корки до корки; чинить дрейф, устаревшие даты, мёртвые ссылки; всё, что требует решения владельца, заносить в `CHANGELOG` вопросом, а не молча.
4. **Перед любым релизом** — двуязычная проверка `VERSIONING` + `CHANGELOG`.

## 6. Правила, которые никогда не гнутся

1. **PHILOSOPHY главенствует над всем** (§3 того файла включает память агентов).
2. **Нет незадокументированных решений.** Если решили в чате — решено не будет, пока не написано, не датировано и не лежит в нужном файле.
3. **Оба языка или ничего.** Одноязычное изменение блокирует коммит.
4. **Роадмап — правда про «когда».** Если в `ROADMAP` стоит `[ ]` — не начато, что бы ни помнилось.
5. **Ассетам нужны лицензии.** В `FREE-3D-MODELS` не попадает ничего без URL + лицензии + формата, и без лицензии ничего не попадает в игру.
