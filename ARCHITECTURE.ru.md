# Архитектура
**[English version of this file →](ARCHITECTURE.md)**

Как устроен LAST CALL. [PHILOSOPHY.ru.md](PHILOSOPHY.ru.md) говорит, что это и почему; при расхождении побеждает он. [ROADMAP.ru.md](ROADMAP.ru.md) говорит, в каком порядке это строится.

Цель: **Unreal Engine 5 (5.4+), C++ как основной язык, Blueprints для итераций, PC в первую очередь.**

## 1. Форма проекта

Один проект UE5, один игровой таргет, инструменты — вне рантайма:

```
LastCall/                          проект Unreal
  Source/LastCall/                 игровой модуль (C++)
    Core/                          фазовые часы, сохранения, сервисы, события
    Bar/                           наливание, инвентарь, улучшения, крафт
    Social/                        клиенты, настроения, диалоги, фракции
    Night/                         стелс, бой, выбивание долгов, обыски
    Coop/                          репликация, роли, сессии
    UI/                            HUD, меню, виджеты (API к Blueprint)
  Source/LastCallTools/            editor-only команды (импорт, валидация, запекание)
  Content/                         карты, меши, материалы, DataTables
  Data/                            истина в тексте: JSON/YAML в git
tools/                             CLI на Rust (или Zig): пайплайн, линтеры
docs/                              дизайн-документация, двуязычная
```

Два правила против распадения:

1. **Дизайн-данные живут в `Data/` текстом** (диалоги, рецепты, клиенты, баланс) и на сборке компилируются в DataTables. Никогда не балансируем игру только внутри `.uasset`.
2. **Всё, что дизайнер правит каждую неделю, — данные; всё, что имеет конечный автомат, — C++.** Blueprints — для подачи и проводки, но не для правил, которые нужно тестировать.

## 2. Цикл дня

Игра живёт часами, а не потоком уровней. Одна сессия = один игровой день.

```
Утро (Подготовка)  ->  Смена (День/Вечер)  ->  Ночь (Экшн/Стелс)  ->  Итог -> следующий день
      ^                       ^                        ^
      |                       |                        |
 экономические системы   социальное + жидкости   боевые/стелс-системы
```

`ULCPhaseManager` — единственный владелец текущей фазы. Он:

- включает/выключает наборы подсистем по фазе (каждая подсистема декларирует фазы своей жизни);
- поднимает `FOnPhaseChanged`, на который слушают UI, музыка и AI;
- сохраняет границу фазы в сейв, чтобы выйти и вернуться на том же наливании.

Переходы между фазами — **единственные точки загрузки** в игре (см. PHILOSOPHY §8).

## 3. Основные подсистемы

| Подсистема | Префикс класса | Ответственность |
| :--- | :--- | :--- |
| Фазовые часы | `ULCPhaseManager` | Конечный автомат фаз, расписание, граница сейва |
| Экономика | `ULCEconomyComponent` | Деньги, поставщики, суточный сток, займы |
| Жидкости / наливание | `ULCLiquidSystem` + `FLCPourSolver` | Наклон бутылки, струя, объём, пролитое, правила смешивания |
| Коктейли | `ULCRecipeLibrary` | Рецепты (данные), проверка комбо, фирменные напитки |
| Крафт | `ULCInfusionSystem` | Собственные сиропы и настойки как новые строки данных |
| Клиенты | `ULCCustomerComponent` | Настроение, терпение, заказ, приметы языка тела |
| Диалоги | `ULCDialogueRunner` | Деревья на данных, условия, флаги подслушивания |
| Фракции | `ULCFactionSystem` | Репутация у трёх группировок + «шум» полиции |
| Навыки | `ULCSkillTree` | Флейринг, Психология, Крепкие нервы, Алхимия |
| Угроза / шестое чувство | `ULCThreatSensor` | Оценка агрессии: «кто здесь, чтобы кого-то убить» |
| Ночные действия | `ULCNightDirector` | Заказы «на вынос», выбивание долгов, расследования |
| Обыски | `ULCRaidDirector` | Просмотр полицией, сокрытие улик, отвлечение |
| Рост заведения | `ULCVenueUpgrade` | Планировка, VIP-зона, этажи, уровень казино |
| Кооп | `ULCCoopSession` | Роли, репликация, делегирование под нагрузкой |
| Сохранения | `ULCSaveSystem` | Один слот, гранулярность — день, без отката (последствия цепляются) |
| Сервисы | `FLCServices` | Точка доступа к вышеперечисленному, инжект на старте |

Каждая подсистема — `UObject`-компонент или чистый сервис: **ни один игровой класс не лезет внутрь чужой подсистемы**; общение между системами — через шину событий (`FOnPhaseChanged`, `FOnCustomerServed`, `FOnHeatRaised`, …). Именно это делает смену фаз дешёвой.

Несколько подсистем несят свою логику в виде ядер на чистом C++17: `Bar/PourSolverCore` (наклон → расход → объём/разлив, качество комбо), `Bar/RecipeLibraryCore` (файлы рецептов → спеки солвера), `Bar/LiquidCore` (слоёные стаканы, пена, журнал пролитого), `Bar/InteractionCore` (роли, лучшее оружие, прочность), `Customers/CustomerReactionCore` (терпение, шок, уход, пороги реакций), `Customers/CustomerCore` (персонажи, чтение примет, полосы угрозы), `Social/SocialCore` (фракции, реакции, ledger репутации), `Crafting/CraftingCore` (настойки/сиропы, исходы крафта), `Customers/OrderCore` (валидность заказа, исходы подачи, чаевые), `Core/DayScheduleCore` (машина фаз, таймеры, границы сейва), `Core/SaveStateCore` (версионированный payload сейва), `Core/ConsequenceLogCore` (флаги последствий со штампом дня), `Core/SkillsCore` (покупка навыков, агрегация эффектов), `Economy/EconomyCore` (поставщики, дрейф цен, журнал утра) и `Dialogue/DialogueRunnerCore` (диалоговые графы поверх состояния мира). В них нет типов Unreal, поэтому `scripts/test-*.sh` (и в CI) проверяют математику и правила без установленного движка; UE-лицевые классы (`FLCPourSolver`, `ULCCustomerComponent`, `ULCPhaseManager`, ...) оборачивают ядра и добавляют рендер, анимацию и репликацию. Тюнинг живёт в `Data/Balance/core.json`, а тесты следят, чтобы код и данные не разъезжались. `Core/JsonCore` — общий строгий JSON-ридер, которым ядра читают реальные файлы из `Data/` без движка.

## 4. Подсистема жидкостей (ключевая технология)

Готовой физики бармена нет ни в одном движке, поэтому мы делаем *убедительную* аппроксимацию, а не полный CFD-расчёт:

- **Налив:** бутылка — наклоняемое твёрдое тело; `FLCPourSolver` интегрирует ленту струи: угол наклона → расход (кривая вроде Бернулли с вязкостью на жидкость), струя идёт по гравитации с лёгким распылением и попадает в коллизию стакана.
- **Объём в стакане:** стакан держит послойные жидкости (цвет, непрозрачность, пена). Правила смешивания проверяют порядок, скорость и непрерывность налива — это и есть система «Коктейль-Комбо», считается из вывода солвера, но никогда из нажатий кнопок.
- **Провал:** перелив поднимает уровень; переполнение спавнит декали и лужу, на которую клиент реагирует. Медленно — расход терпения (см. социальное).
- **Рендер:** ленты и метаболы Niagara, преломление/поглощение в материалах стекла, конденсат и лёд слоями материалов (см. [docs/ART-BIBLE.ru.md](docs/ART-BIBLE.ru.md)).
- **Стоимость:** солвер считается только для активно наливаемого напитка, фиксированные 30 Гц с интерполяцией; глобальной сетки жидкости нет.

Интерфейсы: `IPourable` (стакан), `IPourSource` (бутылка, кран, сифон), `FMixingRules` (данные: окна скорости, порядок слоёв, ключи комбо).

## 5. Социальная подсистема

- `ULCCustomerComponent` держит **терпение** и **настроение** как флоаты, тающие/растущие по тику фазы.
- **Приметы:** набор анимаций и состояний иконки («хочет напиться», «хочет поговорить», «пришёл убить»), которые ведёт `ULCThreatSensor`; навык Психологии открывает полный набор.
- **Последствия:** прерывание истории поднимает фракционно значимые флаги; таблица реакций клиента — данные (`Data/Customers/*.json`).
- Диалог **прерываемый**: начатый налив может срубить реплику, и дерево это записывает. Это первоклассное событие, а не досада интерфейса.

## 6. Ночь, угроза и обыски

- Ночь — отдельный режим со своим набором управления (укрытие, взаимодействие, бросок), переиспользующий бар как уровень.
- `ULCRaidDirector` запускает обыск: уликам вешаются hide-теги; NPC-напарник прячет их, пока игрок проходит проверку на разговоре/отвлечении. Провал = «шум», а не game over.
- Бой редок и смертелен: стрелять можно, но задуманный выигрыш — деэскалация (налить, поговорить, закрыть дверь).

## 7. Данные и диалоги

```
Data/
  Recipes/*.json        рецепты коктейлей, ключи комбо, эффекты
  Customers/*.json      завсегдатаи, расписания, истории, реакции
  Dialogue/*.json       деревья, условия, прерывания
  Skills/*.json         рёбра древа навыков и цены
  Balance/*.json        тюнинг терпения/настроения, цены, чаевые
  Localization/         en.json, ru.json — нативно на обоих языках (решение владельца 13.10.2026), двуязычие игры зеркалит документацию
```

- Диалоги — JSON с условными узлами; `tools/lc-dialogue-lint` (Rust) проверяет достижимость узлов, отсутствующие ключи локализации и тупики в CI.
- Ключи локализации общие для UI и диалогов; **линт парности роняет сборку, если ключа не хватает на любом из языков** — ни один язык не является вторичным по отношению к другому.

## 8. Мультиплеер (кооп 2–4)

- Listen-server, репликация UE; хост считает симуляцию, клиенты владеют своей ролью.
- Роли (бармен, официант, вышибала, диджей) отображаются на реплицируемые компоненты; толпа — на сервере, косметика — реплицируется.
- Кооп — **режим поверх того же цикла дня**, а не отдельная игра: менеджер фаз живёт только на сервере.
- Сетевой сбой = пауза, никогда молчаливый десинк (дизайн-решение; см. [docs/GAME-DESIGN.ru.md](docs/GAME-DESIGN.ru.md) §Мультиплеер).

## 9. Сохранения и последствия

- Один слот на профиль, запись на границах фаз; автосейв внутри фазы есть, но последствия применяются сразу (PHILOSOPHY §5: провалы становятся историями).
- В сейве: день, фаза, деньги, сток, репутация фракций, «шум», выученные рецепты, узлы навыков, сюжетные флаги, уровень заведения.
- Не сохраняется: состояние симуляции жидкости (пересчитывается), косметические настройки (user config движка).

## 10. Тесты

| Тип | Что | Инструменты |
| :--- | :--- | :--- |
| Юнит | кривые солвера, оценка комбо, математика экономики, условия диалогов | Automation-тесты UE, CI на Linux + Windows |
| Данные | схемы для всего в `Data/`, линт диалогов, полнота локализации | CLI на Rust в `tools/`, до каждой сборки |
| Сценарии | скриптованный полный день: подготовка → N клиентов → закрытие → ночь | headless-запуск UE — гейт вех из ROADMAP |
| Ручные | ощущение налива, читаемость примет, нуар-освещение | чек-лист на каждую веху в ROADMAP |

Веха закрывается только когда её **пользовательский путь проходит от начала до конца** — сценарным тестом или живым прогоном, — а не когда зелёные юниты.
