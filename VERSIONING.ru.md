# Версионирование
**[English version of this file →](VERSIONING.md)**

У LAST CALL два канала релизов и по одной схеме версии на канал. Схема повторяет [двухуровневую идею FlashAgent](https://github.com/flashback7766/FlashAgent) — счётчик сборок плюс SemVer — адаптированную для игры с редактором и контентом.

## Форматы

| Канал | Формат | Пример | Значение |
|---|---|---|---|
| Dev / nightly | `d<N>` | `d42` | Локальный счётчик сборок. Только растёт. Игрокам никогда не выдаётся. |
| Beta | `b<N>` | `b17` | Счётчик сборок для плейтестов. Только растёт. |
| Stable | `v<MAJOR>.<MINOR>.<PATCH>+b<N>` | `v0.3.0+b17` | Релиз SemVer, отрезанный от бета-сборки `N`. |

- Часть `+b<N>` — build metadata из SemVer, и **при сравнении она имеет приоритет**, в том числе между стейблами: `v0.4.0+b18 < v0.3.0+b19`.
- Ведущая `v` необязательна, `v1.2` означает `v1.2.0`.
- Правила до 1.0, пока идёт производство: MINOR несёт контент и фичи, PATCH — фиксы. После 1.0: MINOR = контент/патчи, PATCH = хотфиксы, MAJOR = то, на что полагаются игроки, меняет смысл.
- Сборка `d<N>` не покидает команду; порядка относительно беты у неё нет.

## Сравнение

Одно правило, используемое везде:

1. Версии с номером сборки сравниваются сначала по `N`, включая стейблы: `v1.0.0+b30 < v0.9.0+b31`.
2. Стейблы с равной сборкой сравниваются по `MAJOR.MINOR.PATCH`.
3. При равной сборке новее стейбл: `b17 < v0.3.0+b17 < b18`.
4. Старый стейбл без `+b<N>` новее любой нумерованной сборки; два ненумерованных стейбла сравниваются по `MAJOR.MINOR.PATCH`.

## Что сообщает сборка

- **В игре:** Справка в настройках показывает полную версию, канал и версию движка.
- **Краш-отчёты (только локально):** версия прикладывается к логу; ничего не выгружается (PHILOSOPHY §3: без телеметрии).
- **Совместимость сейвов:** сейв несёт `saveVersion`; сейв из более новой сборки отклоняется, старые мигрируются вперёд `ULCSaveSystem`, миграция логируется. Миграция никогда не выполняется для сейва *новее* — без молчаливой потери данных.

## Сборка релиза

Бета-сборка (обычный случай). Сначала раздел в `CHANGELOG.md` (и его двойник `.ru.md`), подписанный точной версией:

```markdown
## b18 — короткий заголовок
```

Затем поднимите `BuildVersion` в настройках проекта, закоммитьте пару чейнджлога вместе с бампом как `Release b18: короткий заголовок` и поставьте тег `b18` на этот коммит. Опубликованный тег никогда не переносится; скрипт (когда появится `tools/lc-release`) останавливается, если тег уже есть, в чейнджлоге нет раздела или есть незакоммиченные изменения.

Стейбл-релиз, отрезанный от свежайшей бета-сборки. Раздел чейнджлога снова первый, подписанный полной версией:

```markdown
## v0.3.0+b18 — короткий заголовок
```

Тот же коммит тегируется `v0.3.0+b18`.

### Как выбирать MAJOR.MINOR.PATCH

- **PATCH**: только фиксы — краши, баги баланса, опечатки на обоих языках.
- **MINOR**: новый контент или фичи; существующие сейвы работают (мигрируются).
- **MAJOR**: то, на что полагаются игроки, перестаёт работать как раньше (ломается формат сейва, схема управления).

Номера бета-сборок переживают стейблы: следующая бета после `v0.3.0+b18` — `b19` или выше.

## Каналы

| Канал | Аудитория | Содержимое |
|---|---|---|
| `dev` | команда | сборки `d<N>`, могут не стартовать |
| `beta` | плейтестеры | сборки `b<N>` и стейблы новее их |
| `stable` | игроки | только стейбл-релизы |

Апдейтер (в сторовых сборках) двигается только вперёд по своему каналу, по правилу сравнения выше.
